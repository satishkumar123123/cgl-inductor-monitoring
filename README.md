# CGL Dashboard

**CGL Inductor Daily Monitoring System** — a full-stack industrial dashboard
for the Electrical Department (APL Apollo Building Products Ltd.) to record,
import, review, and chart daily inductor readings for the Main Pot
(Inductors A–D) and PM Pot (Inductors A–B), each split into High /
Intermediate levels across 17 electrical parameters.

```
cgl-dashboard/
├── frontend/       React + Vite + Tailwind CSS + Recharts + SheetJS
├── backend/        Node.js + Express + MongoDB Atlas (Mongoose) + JWT + Multer
├── docs/           API reference and deployment guide
├── sample-data/    Example daily_inductor_data document (JSON)
├── sample-excel/   Ready-to-use Excel template matching the auto-mapper
└── README.md       (this file)
```

## Features

- **JWT login** with three roles: Admin, Engineer, Operator (Admin-only delete)
- **Editable data-entry table** for Main Pot (A–D) and PM Pot (A–B), High/Intermediate levels, 17 parameters, numeric-only validation
- **Excel upload** with automatic sheet detection and fuzzy row/column mapping — ignores case, spacing, brackets, and units
- Manual editing of imported values, Save / Update / Delete
- **Search by date** and a **History** page (date range + text search)
- Download Sample Excel, Export Excel, Export PDF (print), Print
- 11 Recharts visualizations + 8 summary cards
- Conditional formatting on Current / PF / Voltage thresholds
- Polished dark industrial theme, responsive layout (including a mobile drawer sidebar), toast notifications, confirm dialogs, loading states
- **PM Pot & Main Pot Analysis Reports** — pick a saved date, generate a professional report with tables, 5 charts, auto-calculated stats, automatic industrial observations, operator/engineer remarks, and a signature block; download as PDF/Excel or print
- **Daily Production & Power Consumption** tracking — main/PM pot power, production (metal charging), dross generation, auto-calculated Power/Ton and Dross %, full CRUD (create, edit any saved date, delete with confirmation), 6 trend charts, date/month/year/shift filters
- **Monthly & Yearly Reports** — Total/Average Production, Power, Dross, Power/Ton, Dross %, Highest/Lowest Consumption Day, Best/Worst Efficiency Day (by power-per-ton), automatic charts, downloadable as PDF/Excel or printed
- **Industrial Analysis Engine** — a reusable module (`backend/services/analysisService.js`) that runs on every report: structured observations with severity (current/voltage imbalance, PF status, power trend vs the previous day, per-inductor overload/underload, high impedance, resistance variation, conductance abnormal, safety-limit flags), a 0–100 Health Score, an Equipment Status badge (Excellent/Good/Normal/Needs Attention/Critical), and plain-English recommendations — all shown with colored severity badges on the report pages
- **Report History** — every generated report logged (collection `report_history`) with type, split Generated Date/Generated Time, format, generated by; **Preview** (inline modal, no navigation), **Download Again** (one click, re-generates and re-triggers the original PDF/Excel/print), and Delete (Admin), all paginated
- **Audit Logs** (Admin only) — every create/update/delete request across the API is logged automatically (collection `audit_logs`), viewable and filterable by user/method/date at `/audit-logs`
- **Reliability & performance** — global React error boundary (a render crash shows a recovery screen instead of a blank app), loading skeletons on all major list/report pages, route-level code-splitting (`React.lazy`) so heavy pages/libraries only load when visited, and backend hardening (`helmet`, gzip `compression`, rate-limited login, paginated list endpoints)
- **Analytics Dashboard** — combined production, power, and power-factor performance with 9 Recharts visualizations (daily power/production/power-per-ton/dross trends, power vs production, main/PM pot power, monthly & yearly comparison) and 8 summary cards, filterable by date range, month, year, and shift

## Quick start

### 1. MongoDB Atlas

Create a free cluster and get a connection string — see
[`docs/DEPLOYMENT.md`](docs/DEPLOYMENT.md#mongodb-atlas) for step-by-step
instructions. You'll paste this into `backend/.env` as `MONGO_URI`.

### 2. Backend

```bash
cd backend
npm install
cp .env.example .env
# edit .env: set MONGO_URI and JWT_SECRET
npm run seed     # creates demo users: admin/admin123, engineer/engineer123, operator/operator123
npm run dev      # starts on http://localhost:5000
```

### 3. Frontend

```bash
cd frontend
npm install
cp .env.example .env
# VITE_API_URL=http://localhost:5000 (default is already correct for local dev)
npm run dev      # starts on http://localhost:5173
```

Open http://localhost:5173, log in with one of the seeded accounts, and
you're in.

## Environment variables

**backend/.env**
```
PORT=5000
NODE_ENV=development
MONGO_URI=mongodb+srv://<user>:<password>@<cluster>.mongodb.net/cgl_dashboard?retryWrites=true&w=majority
JWT_SECRET=replace_with_a_long_random_secret
JWT_EXPIRES_IN=7d
CLIENT_ORIGIN=http://localhost:5173
```

**frontend/.env**
```
VITE_API_URL=http://localhost:5000
```

## Notes & assumptions

- Conditional-formatting thresholds (Current/PF/Voltage) are reasonable
  defaults — adjust them in `frontend/utils/conditionalFormat.js` to match
  your plant's actual limits.
- Excel row/column matching lives in two places kept in sync by design:
  `frontend/utils/excelMapper.js` (instant client-side preview) and
  `backend/services/excelMappingService.js` (source of truth once saved via
  `/api/upload-excel`).
- Roles: Admin/Engineer/Operator can all create and update readings; only
  Admin can delete. Adjust `backend/middleware/roleMiddleware.js` usage in
  `backend/routes/dataRoutes.js` to change this policy.
