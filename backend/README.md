# CGL Dashboard — Backend

Express + MongoDB Atlas REST API for the CGL Inductor Daily Monitoring System.

## Setup

```bash
cd backend
npm install
cp .env.example .env
```

Edit `.env`:

```
PORT=5000
MONGO_URI=mongodb+srv://<user>:<password>@<cluster>.mongodb.net/cgl_dashboard?retryWrites=true&w=majority
JWT_SECRET=<a long random string>
CLIENT_ORIGIN=http://localhost:5173
```

Seed three demo logins (Admin / Engineer / Operator):

```bash
npm run seed
```

Run the API:

```bash
npm run dev     # nodemon, auto-reload
# or
npm start
```

The API listens on `http://localhost:5000` by default.

## Collection

`daily_inductor_data` — see `models/DailyInductorData.js`. One document per
calendar date, holding Main Pot (A–D) and PM Pot (A–B) readings, each split
into High / Intermediate levels across 17 parameters.

## Endpoints

| Method | Path                | Auth        | Purpose                              |
|--------|---------------------|-------------|----------------------------------------|
| POST   | `/api/auth/login`   | —           | Log in, returns JWT + user             |
| GET    | `/api/auth/me`       | Bearer JWT  | Current user info                      |
| POST   | `/api/data`          | Bearer JWT  | Create a new day's record              |
| GET    | `/api/data/:date`    | Bearer JWT  | Load a day's record                    |
| PUT    | `/api/data/:date`    | Bearer JWT  | Upsert (Save/Update)                   |
| DELETE | `/api/data/:date`    | Admin only  | Delete a day's record                  |
| POST   | `/api/upload-excel`  | Bearer JWT  | Upload & auto-map an Excel sheet       |
| GET    | `/api/history`       | Bearer JWT  | List saved dates (filter by date/search)|
| GET    | `/api/reports/pm-pot/:date`   | Bearer JWT | PM Pot Analysis Report data + auto observations |
| GET    | `/api/reports/main-pot/:date` | Bearer JWT | Main Pot Analysis Report data + auto observations |
| GET    | `/api/reports/preview/:reportType/:date` | Bearer JWT | Lightweight preview (reportType = `pm-pot`/`main-pot`) |
| POST   | `/api/reports/log`            | Bearer JWT | Log a generated report (History + Analysis audit trail) |
| GET    | `/api/reports/history`        | Bearer JWT | Paginated report generation history |
| DELETE | `/api/reports/history/:id`    | Admin only | Delete a report history entry |
| POST/GET/PUT/DELETE | `/api/power(/:date)` | Bearer JWT (DELETE = Admin) | Daily power/production/dross CRUD |
| GET    | `/api/power/monthly?year=&month=` | Bearer JWT | Monthly analysis summary |
| GET    | `/api/power/yearly?year=`         | Bearer JWT | Yearly analysis summary |
| GET    | `/api/analytics?from=&to=&month=&year=&shift=` | Bearer JWT | Combined production/power/PF analytics for the dashboard |
| GET    | `/api/audit-logs?user=&method=&from=&to=` | Admin only | Paginated audit trail of every mutating request |

All protected routes expect `Authorization: Bearer <token>`.

## Additional collections (Reports & Power modules)

- `daily_power_consumption` — one document per date: main/PM pot power, overall power, metal charging, dross generation, operator, shift, remarks, and derived `powerPerTon`/`drossPercent`.
- `report_history` — a log entry every time a report is generated/downloaded/printed (report type, generated date/time split for display, format, generated by). Renamed from the earlier `generated_reports` collection.
- `analysis_history` — the computed statistics, structured observations (with severity), Health Score, Equipment Status, and recommendations for every PM/Main Pot report generated, kept as an audit trail independent of the report file itself.
- `audit_logs` — every mutating request (create/update/delete, login, uploads) across the whole API, logged automatically by `middleware/auditLogger.js`. View via `GET /api/audit-logs` (Admin only).

## Excel upload

`POST /api/upload-excel` — `multipart/form-data` with fields:
- `file` — `.xlsx`/`.xls` workbook
- `date` — `YYYY-MM-DD`

Mapping logic lives in `services/excelMappingService.js`. Row labels are
matched by keyword groups (case, spacing, brackets, and units are ignored),
and column headers like `"A High"` / `"B Intermediate"` are parsed into
inductor + level. Non-numeric cells are skipped and reported in `errors`;
unrecognised row labels are reported in `unmatched`.

## Roles

- **Admin** — full access, including delete
- **Engineer** — create/update readings
- **Operator** — create/update readings (typically day-to-day data entry)

Adjust `middleware/roleMiddleware.js` usage in `routes/dataRoutes.js` to
tighten or loosen this as needed.
